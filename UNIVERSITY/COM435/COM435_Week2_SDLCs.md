# Prototyping

![[Prototyping.png]]

**Advantages**  
• Increased user involvement in the product even before its implementation.  
• The users get a better understanding of the system being developed.  
• Reduces time and cost as the problems can be detected much earlier.  
• Quicker user feedback is available leading to better solutions.  
• Missing functionality can be identified easily.  
• Confusing or difficult functions can be identified.

**Disadvantages**  
• Risk of confusion between between prototypes and actual systems  
• Technical difficulties using already development prototypes for the basis of actual  
systems, may not be technical feasible or may include defects that later will be difficult  
and cost more to fix.  
• Risk of not performing enough requirements analysis because of the fixation with the  
prototype.  
• Prototypes and therefore actual systems can easily have feature creep and move away  
from original plans

# Rapid Application Development

![[RapidApplicationDevelopment.png]]

**Advantages**  
• Features delivered early.  
• Speed - it’s fast and concentrates on the minimal deliverables no zombie features.  
• Cost effective due to speed, ie. no time wasted on unwanted features, client is happy  
• Developers are happy too as they have more contact with the clients to keep them satisfied

**Disadvantages**  
• Hard to scale beyond a single team.  
• Heavy commitment from the client  
• Interface-focus - client judges quality on what they can see and interact with therefore  
development give the front-end more focus and forego best practice and attention to  
detail on the backend

# Spiral

![[Spiral.png]]

**Advantages**  
• Suitable for large projects: Spiral models are recommended when the project is large,  
bulky or complex to develop.  
• Risk Handling: There are a lot of projects that have un-estimated risks involved with  
them. For such projects, the spiral model is the best SDLC model to pursue because it  
can analyse risk as well as handling risks at each phase of development.  
• Customer Satisfaction: Customers can witness the development of product at every  
stage and thus, they can let themselves habituated with the system and throw  
feedbacks accordingly before the final product is made. Space for customer feedback.  
• Requirements flexibility: All the specific requirements needed at later stages can be  
included precisely if the development is done using this mode
 
**Disadvantages**  
• Can be costly to run and not suited to smaller projects.  
• Can be difficult to control time and therefore budget, could run indefinitely, i.e not  
clear definition of done set out.  
• Requires risk assessment expertise.  
• Moderate documentation required while following each of the phases.

# **Lean Principles**

| #   | Lean Principles             |
| --- | --------------------------- |
| 1   | Eliminate Waste             |
| 2   | Amplify Learning            |
| 3   | Decide as Late as Possible  |
| 4   | Deliver as Fast as Possible |
| 5   | Empower the Team            |
| 6   | Build Integrity In          |
| 7   | See the Whole               |

| **1. Eliminate Waste**                                                                                     |
| ---------------------------------------------------------------------------------------------------------- |
| Waste is anything that consumes time, money, effort, or resources without creating value for the customer. |
| **Examples:**                                                                                              |
| • Zombie features                                                                                          |
| • Excessive documentation                                                                                  |
| • Waiting on Approvals                                                                                     |
| • Context switching                                                                                        |
| • Fixing avoidable defects                                                                                 |
| • Long meeting with little outcome                                                                         |

| **2. Amplify Learning**                                                                                       |
| ------------------------------------------------------------------------------------------------------------- |
| Lean assumes that uncertainty exists in every project.                                                        |
| Rather than trying to predict/plan everything upfront, teams should focus on learning as quickly as possible. |
| Modern software team learn:                                                                                   |
| • User interviews                                                                                             |
| • Experiments                                                                                                 |
| • Prototypes                                                                                                  |
| • Analysis                                                                                                    |
| • Feedback                                                                                                    |
| Why is learning often more valuable than building?                                                            |

| **3. Decide as Late as Possible**                                                      |
| -------------------------------------------------------------------------------------- |
| Can making decisions too early increase project risk?                                  |
| Lean does not mean delaying work.                                                      |
| It means delaying major decisions until enough evidence exists to make good decisions. |
| • Early decisions are often based on assumptions.                                      |
| • Later decisions can be based on facts.                                               |
| • The more uncertainty that exists, the more dangerous premature decisions become      |

| **4. Deliver as Fast as Possible**                                                              |
| ----------------------------------------------------------------------------------------------- |
| Fast delivery also reduces:                                                                     |
| • Inventory                                                                                     |
| • Uncertainty                                                                                   |
| • Opportunity cost                                                                              |
| However, Lean does not mean rushing or lowering quality.                                        |
| It means creating efficient flow through the system.                                            |
| Lean values speed because speed increases feedback.                                             |
| The quicker something reaches a user, the quicker the team learns whether it has created value. |

| **5. Empower the Team**                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------ |
| Empowered teams are generally:                                                                                           |
| • More motivated                                                                                                         |
| • Faster at solving problems                                                                                             |
| • Better at innovation                                                                                                   |
| Management should provide direction and support rather than controlling every detail.                                    |
| Team given:                                                                                                              |
| • Access to customer                                                                                                     |
| • Decision making                                                                                                        |
| • Choosing own commitments                                                                                               |
| Lean assumes the people closest to the work often understand it best.                                                    |
| Instead of requiring every decision to go through management, teams should be trusted to make many decisions themselves. |

| **6. Build Integrity In**                                                                                  |
| ---------------------------------------------------------------------------------------------------------- |
| If quality is ignored, teams eventually slow down because defects become increasingly expensive to fix.    |
| Methods for building integrity include:                                                                    |
| • Refactoring                                                                                              |
| • Automated testing                                                                                        |
| • Continuous integration                                                                                   |
| • Code reviews                                                                                             |
| • Reusable components                                                                                      |
| Integrity means quality.                                                                                   |
| Lean argues that quality should be built into the product from the start rather than inspected at the end. |
| Why is fixing defects early usually cheaper than fixing them later?                                        |

| **7. See the Whole**                                                                          |
| --------------------------------------------------------------------------------------------- |
| Software products involve:                                                                    |
| • Customers                                                                                   |
| • Product managers                                                                            |
| • Designers                                                                                   |
| • Developers                                                                                  |
| • Testers                                                                                     |
| • Operations teams                                                                            |
| • Support teams                                                                               |
| A change affecting one area often affects many others.                                        |
| This principle encourages systems thinking.                                                   |
| Many organisations optimise individual departments rather than optimising the overall system. |
| However, improving one part of a process does not necessarily improve the whole process.      |
| Why might improving one part of a system sometimes make the overall system worse?             |

# Agile VS Lean

| **Agile Philosophy**                                                                                                 | **Lean Philosophy**                                                                                                                       |
| -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Is aimed at executing tasks faster, adapting to changes easier                                                       | Is about Smart development, when you improve virtually everything you do by eliminating anything that doesn’t bring value to the customer |
| Makes the developing process flexible                                                                                | Makes the developing process sustainable                                                                                                  |
| Was initially designed for Software Development, then expanded to Marketing, and is currently applied in other areas | Started from traditional manufacturing and expanded to all existing industries                                                            |
| Action loop: product backlog – sprint backlog – iteration (sprints) – potentially shippable result                   | Action loop: build-measure-learn                                                                                                          |
| Method for demonstrating progress — definition of ‘done’                                                             | Method for demonstrating progress — validated learning                                                                                    |
| Toolkit: sprints, boards, Scrum Master, acceptance tests, user story mapping etc.                                    | Toolkit: hypotheses, split (A/B) tests, customer interviews, funnel and cohort analysis, Customer Success Manager etc.                    |
